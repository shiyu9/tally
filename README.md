# tally — tasks.md を守るプラグイン

Claude Code のセッションが**始まるときに、そのプロジェクトで何が残っているかを見せ**、
**コミットを出した本人に、そのセッションのうちに tasks.md を直させる**プラグイン。
tasks.md へは一切書き込まない。

## 入れかた

```
/plugin marketplace add shiyu9/tally
/plugin install tally@tally
```

環境変数 `TALLY_DISABLE=1` を置くと、両方の hook が完全に無音になります。
一時的にそのセッションだけで試すなら、導入せずに
`claude --plugin-dir <このリポジトリ>/plugins/tally` でも動きます。

必要なもの: Python 3 と `git`（どちらも PATH にあること）。外部パッケージは使いません。

## 何をするか

**SessionStart**（`startup` / `resume` / `clear`。約 105〜200ms）

| | 条件 | 出るもの |
|---|---|---|
| S1 | コミットがまだ1つも無い | 「git init して最初のコミットを」（**プロジェクトごと1回**） |
| S2 | tasks.md が無い | 「tasks.md を作って」 |
| S3 | tasks.md を最後に触ったコミットが HEAD でない | 「`git log --oneline <hash>..HEAD` を見て反映して」 |
| S3d | tasks.md が git 未追跡 | 「`git add tasks.md` してコミットして」（**プロジェクトごと1回**） |
| S4 | 未コミットがある | 注入の見出しに「未コミット N 件」（**促さない。状態表示だけ**） |
| S5 | `- [x]` が 20 件超 | 「消し込んで」 |
| S6 | 未チェック項目がある | 項目を **6,144 バイトまで**、記述順に、項目の境界で詰めて注入。切れたら「…他 M 件は tasks.md を参照」 |

**Stop**（毎手番。促しはセッション中1回）

| | 条件 | 動き |
|---|---|---|
| T0 | `stop_hook_active` | 即終了（公式のループガード） |
| T1 | このセッションで促し済み | 即終了 |
| T2 | セッション中にコミットが出て、tasks.md がそれに追いついておらず、未チェックが1件以上 | 反映を促し、マーカーを書く |

T2 の「セッション中に」は、SessionStart が記録した**開始時の HEAD** と現在の HEAD を
比べて判定する。

**同じ促しが3セッション連続で無視されたら、その項目は以後黙る**（S2・S3・S5 が対象）。
条件が偽になった＝直されたら、カウンタは 0 に戻る。

## 絶対条件

- **tasks.md へは書かない** — hook の前後で内容も mtime も変わらない
- **他プラグインのファイルは見ない** — 開くのは `<cwd>/tasks.md`、`<cwd>` の git
  リポジトリ、`~/.claude/tally/`（自分の状態）の3か所だけ
- **例外は握りつぶして無音** — stdin 不正・cwd 不在・git 無し・状態破損・状態が書けない、
  のどれでも stdout は空で exit 0

3つとも試験で担保している（試験は作者の作業リポジトリにあり、ここには含まれていない）。

## tasks.md の書きかた（強制も検出もしない、ただの推奨）

```markdown
# tasks

- [ ] **やること** — 一行で何をするか
  手がかり: src/view/motion.ts:120
  再開条件: 同型がもう1件出たら（保留にした理由と、戻す条件を継続行に書く）
- [x] 済んだもの（行ごと消すのが基本。20件を超えると S5 が消し込みを促す）
```

- 注入されるのは `- [ ]` の項目と、その**継続行**（字下げされた行）、および直上の見出し
- **「保留」という節は持たない。** 保留も `- [ ]` 項目として書き、理由・再開条件・
  待っているものを継続行に書く（実測した11個の tasks.md に「保留」という見出しは1つも
  無く、実物は「未解決」「見送り」「仕様の判断待ち」などばらばらだった）
- **`CLAUDE.md` に `@tasks.md` は書かないこと。** S6 が注入するので二重になる

## 落とした項目（再開条件つき）

- **A1: コミット差分の TODO/FIXME/XXX の件数を添える** — 実測（2026-09-10・11プロジェクト）で
  `<hash>..HEAD` の差分に **1件も無かった**ため落とした。
  **再開条件: コードに TODO/FIXME を残す運用に変わったら戻す。**
- **保留節の節単位注入** — 見出し名が実物で特定できなかった（上記）。
  **再開条件: `## 保留` という節を実際に書く運用が根づいたら戻す。**
- **mtime による鮮度判定** — 編集→コミットの順序上、正しく運用しても mtime は必ず
  古くなる（rally 実測で15秒）。clone や pull でも書き換わる。戻さない。

## 未担保（機械が守っていないもの）

- **S5 の閾値 20 は実測根拠が無い。** 実測の `- [x]` は最大9件で、当面どのプロジェクトでも
  鳴らない。relay:record が完了項目を消していたための 0 なので、relay 撤退後は溜まる方向へ
  変わる見込み。**1か月運用して鳴らなければ下げる。**
- **`source=resume` の実機挙動は未確認。** 同じ session_id が渡らなければ起点が作り直され、
  T2 が前セッションのコミットで鳴りうる。
- **保留の持ち越しは作業セッションの手作業依存。** tally は保留節を持たない。
- **判断だけのタスク（コードに痕跡が残らないもの）は取りこぼす。** 頻発したら再検討。
- **「読むパスは3か所だけ」は文字列リテラルの検査。** 実行時に開いたパスの記録では
  検査していない。
- **締めの発言の質はモデルと経路で変わる。** P3（2026-09-11）では、対話セッション（Opus 5）が
  作業内容を具体的に再掲したのに対し、ヘッドレスの haiku は「（実施内容の報告は上記のとおり）」と
  参照で済ませた。促し文の効き方を機械で固定することはできない。
- **「最後の発言だけが届く」経路は `claude -p` だけを確かめた。** リモートコントロールの
  モバイル画面では会話全体が見えると実測したので促し文から「リモート」を外したが、
  他の配信経路（通知・要約など）は見ていない。

## 撤退条件

- hook が Claude Code の更新で **2回以上壊れたら**、hook を捨てて `@tasks.md` だけに戻す。
  検知者は判定部の単体試験（環境に触らないので、壊れたのが Claude Code なのか手元の環境
  なのかを判別できる）
- 同じ促しが **3セッション連続で無視されたら**その項目を止める（自動・実装済み）

## 作り

| ファイル | 役割 |
|---|---|
| `tally_core.py` | **判定部。純関数だけ。** git もファイルも時計も触らず、値を受け取って「何を出すか」と「状態をどう更新するか」を返す。`import` を1つも持たない |
| `tally_io.py` | 外の世界に触る部分。git の呼び出し、tasks.md の読み取り、状態の読み書き |
| `tally_session_start.py` / `tally_stop_hook.py` | hook 本体。stdin/stdout と、上の2つの組み立て |

判定部を純関数に閉じ込めてあるのは、撤退条件の検知者が単体試験だからです。試験が実行環境
（git の有無・時計・ホーム）に依存すると、壊れたのが Claude Code なのか手元の環境なのかが
判別できなくなります。

**状態の置き場所**（tally が書き込む唯一の場所）:

| 入れ物 | 場所 | 中身 |
|---|---|---|
| セッション状態 | `~/.claude/tally/session/<キー>.json` | T2 の起点となる開始時の HEAD、促し済みの印。TTL 7日 |
| プロジェクト状態 | `~/.claude/tally/project/<キー>.json` | S1・S3d の「1回だけ」の印、連続無視のカウンタ。TTL 90日 |

キーはパスの末尾48文字＋64bit FNV-1a（最大65文字）。パスをそのまま名前にすると、深い場所に
あるプロジェクトで Windows の MAX_PATH を超えて書き込みが黙って失敗します。

### 検証について

単体試験（判定部・hook 本体）と E2E（実セッションを起こし、transcript から hook の出力を
生のまま取り出して期待値と突き合わせる）を持っていますが、**どちらも作者の作業リポジトリに
あり、ここには含まれていません**。README に書いてある実測値・しきい値の根拠・撤退条件は、
そこで確かめたものです。

数字が具体的なのは、実在する11個の tasks.md を走査した実測の上に置いているためで、
**別の環境ではしきい値の妥当性が変わりえます**。
